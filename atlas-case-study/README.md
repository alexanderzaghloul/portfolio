# ATLAS — Finance Operations Intelligence

> **Sanitized portfolio case study.** The original prototype was developed during a Finance Operations internship at AXA Partners. No employer source code, confidential data, credentials, internal documentation, or proprietary logic is included here.

## The challenge

KPI reporting, financial data, governance checks, and issue follow-up often lived across disconnected files and manual workflows. That fragmentation made it harder to see what needed attention, who owned the next action, and whether data had passed the right checks.

## What I built

I independently took ATLAS from an initial idea to a working internal software prototype using **JavaScript, Python, HTML, and CSS**. The concept brought several finance-operations needs into one workflow:

- KPI and financial-reporting views
- data-quality and validation checks
- exception and issue tracking
- owner-based follow-up
- governance and audit-oriented status visibility
- structured exports for further review

## How I worked

1. Observed reporting and operational pain points while supporting KPI reporting, accounts receivable, collections, and data analysis.
2. Defined a clearer workflow from source data to review and action.
3. Built a functional prototype outside the original internship scope.
4. Presented the concept to stakeholders.
5. Gathered feedback and refined the product throughout the internship.
6. Documented the prototype's limitations, maintenance needs, and path toward production readiness.

## Outcome

ATLAS received strong internal interest and was evaluated for continued development. The project demonstrated my ability to combine financial analysis, software development, process improvement, stakeholder communication, and data governance.

## What this project taught me

- Start with the operational problem, not the technology.
- Make data quality and ownership visible inside the workflow.
- Treat stakeholder feedback as product input.
- Separate a compelling prototype from a production-ready system.
- Design for governance, privacy, maintainability, and handoff from the beginning.

## Confidentiality

This repository intentionally contains **no ATLAS source code or internal data**. Any public interface shown in my portfolio uses synthetic, illustrative information and recreates only the high-level product thinking—not the employer implementation.
